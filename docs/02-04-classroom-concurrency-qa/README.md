# 02-04 投票：40人同時利用への改修と確認

確認日：2026-10-22。既存の個人アカウント・既存WebアプリURLでGoogle側をバージョン9へ更新。公開範囲やOAuthスコープは変更していない。

## 改修

従来は投票ごとに全回答と送信履歴を読み、スクリプトロックを最大20秒待ち、二つの行を保存し、全体集計まで返していた。40人の保存待ちと4〜5秒周期の閲覧が同時実行枠を消費する構成だった。

投票の受理を永続受信箱への保存とし、結果にはシートと受信箱を合成する。一件の実行だけが最短6秒間隔で複数票を一括反映し、他の閲覧はロックを待たない。全回答の共有キャッシュは日本語でも100KB/項目を超えないよう分割する。初期接続、再試行、10〜16秒周期の結果取得を端末ごとに分散し、手動更新も追加した。

シート反映に失敗しても受信箱を削除しない。途中まで反映した場合や応答が失われた場合の再送でも重複・古い票への巻き戻りを防ぐ。キャッシュは保存先ではない。全員が保存直後に閉じた場合はシートを開くか「保存待ちの回答をシートへ反映」で残りを反映できる。

## 実際のGoogleでの負荷確認

単一ブラウザーの独立した4つのApps Script画面から10人ずつ、40人相当を同時接続。本番と同じjoinPoll・votePoll・readPollを使用した。専用の `testing` 授業に保存し、実授業の全体集計には含めない。終了後、確認用授業の受付を終了した。

| 指標 | 結果 |
| --- | --- |
| 完了人数 | 40 / 40 |
| 回答 | 4課題 × 2回 × 40人 = 320票 |
| 同じ送信の再試行 | 40件。増票なし |
| 各課題の初回・考え直し | すべて40票・40票 |
| 各課題の初回の4選択肢 | すべて10票ずつ |
| 成功したRPCの中央値 | 1,006 ms |
| 成功したRPCの95パーセンタイル | 1,811 ms |
| 一時エラーに対する再試行 | 40回。全員完了 |
| 準備・全720操作・再試行・最終集計の所要時間 | 131.6秒 |

応答時間は成功した一回の通信の値で、再試行の待機時間を含めない。全体の所要時間には開始前の15秒の同期準備が含まれる。40台の実端末や学校回線を再現した試験ではなく、Googleの同時実行・日次上限が無くなるわけではない。

集計値：`google-load-test.json`。画面：`google-load-test.png`。
