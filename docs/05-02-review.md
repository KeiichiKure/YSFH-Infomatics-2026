# 05-02 インターネットの仕組み：レビュー用メモ

2026-09-28。既存の「理数情報ラボ」へ追加した未掲載の単元ページ。旧 `artifact-template-web` と過去単元の視覚・操作スタイルに合わせた。

## 教材の流れ

1. IPv4のビット操作とIPv6の省略前後比較。Windowsのスタートメニューからコマンドプロンプトを開き、`ipconfig /all` でIPv4を探し、相手の番号を教えてもらって `ping -n 4` を自分で入力する実機活動。表示例と応答・タイムアウトの読み方を示す。Webには生徒のIPを入力させない。
2. ICANNのIANA機能 → APNIC → 日本の登録規模 → ISP A社（模型） → 家庭用ルータ（模型）を縦にたどる。最初は住所・個数を隠し、「次へ」で番号が下へ動き、到着後に受取先の範囲と個数が現れる。到着した一段だけを強調し、上の段の要素は再アニメーションしない。2025年末の公開集計では、世界の登録・割り当て済みが約36.87億、APNICの管轄がその約24%（約8.85億）、日本の登録組織分が1億8,874万2,464。提示された約7.51億が同じ基準であることは確認できなかったため、採用しない。2020年のAPNIC統計では日本は2億461万9,520であり、時点や集計法で数値が異なる。`1.0.0.0/8` と `1.0.16.0/20` は公開登録にある範囲の実例で、4,096個は日本の総数ではない。A社以下は部分集合の仮定。家のPC・スマホ・新しく買ったプリンターは全て電源OFFから始める。DHCPなら探索・提案・要求・確定を「次へ」「戻る」で進める。固定IPでは各機器の電源をONにして番号を設定・変更でき、電源を切っても設定は残る。新しいプリンターは未設定から始まり、同じ番号の2台をONにすると両方を赤い衝突状態にする。NAPTは2サーバ、A・B端末、ルータの吹き出しに加え、要求・返事の変換前後の番号を次の送信まで並べて残す。返事用メモの書き込み・照合・宛先書き換えを一段ずつ追う。NAPTなしの比較模型ではメモがなく、返信先を特定できない。
3. 実機のIPv4・マスクを入力。8ビットごとの十進数と0・1を対比し、クリックでIPやマスク境界を変える。無効なマスク操作はクリック位置に吹き出しで理由を示す。大きく表示する `/24` などのプレフィックスも左から1が続く個数と対応する。IPとマスクのANDで求めるのはネットワークアドレスであり、ゲートウェイではない。ホスト部を全て1にしたブロードキャストも示す。教科書の接続できる台数は両端を除く `2^h−2` 個（/24なら254）。発展欄で、このうち1個をルータがゲートウェイとして使う例を示し、他の機器向けは253個と区別する。
4. URL・HTTPS・FQDN・メール・偽装ドメイン・URLの信頼性の7問は選択肢ごとに解説し、全問正解でお祝い表示。co.jp・ed.jp・go.jp・uk・de・com・edu は線で結ぶ組み合わせ問題。
5. いつものDNSに説明用の3件の記憶を初期配置。ルートDNSの住所は最初から設定済みとして別枠に示す。「何を聞く？」の候補はドメイン名を先に表示し、「この名前を調べる」から同じ位置の「次へ」を押し続けて追う。初回はルート → `.jp` → `example.jp` の担当DNSを矢印と問い合わせ内容で追い、紹介された担当DNSの住所を期限つきで記憶する。次の別名は`example.jp`の担当DNSから直接尋ねられる。正確なホスト名の回答が記憶にあれば、さらに短い経路になる。つづり違いはブラウザ風のNXDOMAIN表示。DNSはホスト名のIPを返し、index.htmlはWebサーバが選ぶことを明記。
6. 回線交換とパケット交換を同じ一本の枝分かれした回線で切り替える。メール・印刷・Webの3人は最初から送信待ち。中央の共通回線を細くし、Bからプリンターまでの線を見やすくした。左に送る箱、右のサーバ側に後から作る返事の箱を示し、往復計9個を一個ずつ流す。Aのメールに添付ファイルを付けると箱が6個増え、回線交換ではB/Cの待ち時間が伸び、パケット交換では途中で交代できる。箱は到着してから相手側に表示。回線交換ではAが返事まで終えて手放し、B、Cへと回線を渡す。ルータはDNSでニュースWebまたは動画サーバのIPを調べ、R1から隣へ経路情報を尋ねる模型を段階操作する。R1～R6を押すと各経路表を表示し、「次へ」では確認中のルータへ自動で切り替える。オレンジは現在動く機器、緑枠は下に表示中の経路表と凡例で明示。ニュースWebはR4、動画サーバはR6のみに直結し、R5にはサーバへの直結がない。初回に記録した後は同じサイトをもう一度開き、R1と途中のルータが経路表を見て問い合わせなしに進める。「最初から」で記録を消せる。`198.51.100.80/32` はニュースWeb一台、`198.51.100.0/24` はネットワーク全体を表す。
7. 最終欄は過去単元に合わせ、最初から用語名が見える折りたたみ確認と3問チェック。緑のWeb節番号から活動へ戻る。

## 技術的な線引き

- IANAは家庭や国へ一律に直接割り当てるわけではない。`1.0.0.0/8` と日本向けの `1.0.16.0/20` は公開登録の例。A社・家庭の部分集合は授業用の仮定。203.0.113.x・198.51.100.x・192.0.2.x は学習用に予約された番号で、実接続先ではない。
- DHCPはLAN内の設定を配り、NAPTは通信中のIPとポートを変換する。NAPTなしでプライベートIPをそのまま公開インターネットに出しても返信経路がなく、1つの外側IPを共有するなら対応表なしでは端末を振り分けられない。
- ブロードキャストは端末に割り当てない。ゲートウェイは利用可能な範囲の住所をルータが使うもので、ANDやORの結果そのものではない。/31・/32には `2^h−2` をそのまま使わない。
- `example.jp` はJPRSが例示用として予約した名前。DNSサーバのIP例は資料用で実際のDNSへ問い合わせない。ブラウザ風エラーは学習用の模擬表示。
- ルートDNSの宛先はリゾルバーのroot hintsとして与えられる。委任された`.jp`・`example.jp`の担当DNS情報は有効期限つきでキャッシュできる。模型は期限切れを省略。根拠：[ICANN root hints](https://www.icann.org/en/icann-acronyms-and-terms/root-hints-file-en)、[RFC 1034](https://www.rfc-editor.org/rfc/rfc1034)。
- 回線の比較は回線確立・ヘッダ・伝送遅延を省いた模型。実際にどちらが速いかを断定しない。
- ルータの探索図で広がるのは経路情報のやり取りであり、利用者のデータを無差別に複製する描写ではない。
- 実際の経路表は通信のたびに初めて探索するわけではない。OSPFなどではルータが接続情報を交換して経路表を作る。図の会話と段階操作は初回と記録済みの違いを見せる模型。
