# 02-04 コミュニケーションとメディア

教材は `/YSFH-Infomatics-2026/units/02-04/` にあります。トップページの単元一覧へ追加する操作は別に行います。

## 投票の使い方

個人GoogleアカウントのApps Scriptと非公開のスプレッドシートで運用します。Webアプリは所有者として実行し、アクセスは「全員」。生徒の氏名・メールアドレス・Googleログインは求めません。公開する理由には、名前や実際の個人の事情を書かないでください。

- 「コードなしで、全体投票に参加する」が基本の参加方法です。この保存先にある全授業・全体投票の蓄積を集計します。
- クラス単位で比べるときは、先生がシートの「授業投票」→「新しい授業を作る」で授業名と好きな数字4桁を指定します。生徒はそのコードで参加します。先頭の0も使えます。受付中の授業で同じコードは使えません。
- どちらの参加方法でも、生徒が課題1〜4を自由に選べます。先生による課題の切替や締切操作は不要です。
- 方法の選択は必須です。理由は任意で、書く場合は200字以内です。各課題へ投票した後、その課題の結果を表示します。
- 「もう一度投票する（考え直し）」で2回目を保存します。初回と考え直しは別に集計します。「この回の自分の投票を修正する」は同じ回の票を置き換えます。
- 結果閲覧中は、取得完了から約4〜5秒後に次の自動取得を始めます。Googleの応答時間が加わるため、即時のプッシュ配信ではありません。回答編集中と非表示タブでは取得を休みます。
- 授業を終了するときは「授業」シートの対象授業行を選び、「授業投票」→「授業の受付・閲覧を終了」を使います。理由の非表示・再公開・集計からの除外は「回答」の対象行で行います。終了した授業の票も全体集計に含まれます。

同じブラウザでの修正・再送は票数を増やしません。別の端末・ブラウザでは別の参加者として扱うため、厳密な実人数の集計ではありません。

## Google側のコードを更新するとき

1. `poll/core.cjs`、`poll/Code.gs`、`public/02-04-poll/` のソースを編集します。
2. 教材フォルダーで `node scripts/package_communication_poll.mjs` を実行します。
3. 生成した `poll/google/Code.gs` と `poll/google/Index.html` を、既存のApps Scriptの「コード.gs」「Index.html」へコピーして保存します。
4. 「デプロイ」→「デプロイを管理」で既存Webアプリを編集し、「新バージョン」をデプロイします。保存だけでは公開中の画面は更新されません。同じデプロイを更新すればURLは変わりません。
5. 教材と先生用スプレッドシートを再読み込みします。

新しい保存先へコピーするときは、コピー先で「保存先を初期設定（コピー後も実行）」を実行し、別のWebアプリとして公開します。生徒へ保存先シートを公開する必要はありません。

## 教材をビルドする

接続先は `public/02-04-poll/config.json` の `webAppUrl` です。末尾が `/exec` の公開URLを指定します。URLを変えた場合は教材も再ビルドします。

```powershell
$env:PAGES_BASE_PATH = '/YSFH-Infomatics-2026'
npm.cmd run build
```

GitHubのmainブランチへのpushで、既存のGitHub Pages公開処理が教材をビルドします。

## Googleへ送らずに確認する

ビルド後、`node scripts/serve_communication_poll.mjs` を起動し、以下を開きます。

`http://127.0.0.1:3065/YSFH-Infomatics-2026/units/02-04/?poll=local`

新しいローカル保存先の初期コードは `0123` です。先生用リンクは `tmp/02-04-poll/teacher-url.txt` に出力されます。このフォルダーには確認用回答・管理情報が入るため、Gitの管理対象から除外しています。

```powershell
node --experimental-strip-types --test tests/communication-*.test.mjs
node scripts/test_communication_poll_api.mjs
node scripts/test_communication_poll_free_api.mjs
```

APIテストは確認用サーバーを起動して実行します。40人×4課題×2回の同時送信と再送を確認します。これはローカル処理の検証であり、Googleの授業規模での応答速度を保証するものではありません。

実データ体験はUCIのBike Sharingを使用しています。出典・ライセンス・列の対応は `public/data/02-04/provenance.json` と教材内に記載しています。通信史・人数のイラストは本教材用の生成画像です。
