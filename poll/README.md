# 02-04 コミュニケーションとメディア

教材は `/YSFH-Infomatics-2026/units/02-04/` にあります。トップページの単元一覧へ追加する操作は別に行います。

## 投票の使い方

個人GoogleアカウントのApps Scriptと非公開のスプレッドシートで運用します。Webアプリは所有者として実行し、アクセスは「全員」。生徒の氏名・メールアドレス・Googleログインは求めません。公開する理由には、名前や実際の個人の事情を書かないでください。

- 「コードなしで、全体投票に参加する」が基本の参加方法です。この保存先にある全授業・全体投票の蓄積を集計します。
- 教員など投票しない方は「投票せずに結果を見る」で、全体の票数・理由をそのまま閲覧できます。4桁コードの欄の「この授業の結果だけを見る」ではクラス結果を開き、「全投票結果を見る」で全体とも比較できます。終了したクラスも閲覧できます。いずれも閲覧用の票は作らず、既存の自分の投票や下書きも変更しません。閲覧用の接続情報ではサーバーも投票を拒否します。
- クラス単位で比べるときは、先生がシートの「授業投票」→「新しい授業を作る」で授業名と好きな数字4桁を指定します。生徒はそのコードで参加します。先頭の0も使えます。受付中の授業で同じコードは使えません。
- 複数クラスは「授業投票」→「一括登録用シートを開く」で「授業登録」シートを開き、A列へ4桁のコード、B列へ授業名を2行目から入力します。D2の「授業コードを授業名にする」にチェックすると、B列は空欄でよく、すべての入力行のコードをそのまま授業名にします。「入力した授業を一括登録」で登録し、C列の結果を確認します。同じコード・授業名を再登録しても授業は増えません。管理用の「授業」シートへ直接行を追加する必要はありません。
- どちらの参加方法でも、生徒が課題1〜4を自由に選べます。先生による課題の切替や締切操作は不要です。
- 方法の選択は必須です。理由は任意で、書く場合は200字以内です。各課題へ投票した後、その課題の結果を表示します。
- 「もう一度投票する（考え直し）」で2回目を保存します。初回と考え直しは別に集計します。「この回の自分の投票を修正する」は同じ回の票を置き換えます。
- 授業コードで参加した結果画面の「全投票結果を見る」は、OFFでそのクラス、ONで全授業とコードなし投票の票数・理由を表示します。初回と考え直しはそれぞれ別に比較できます。表示の切り替えは投票を増やさず、自分の投票先も変えません。
- 結果閲覧中は、取得完了から約10〜16秒後に次の自動取得を始めます。端末ごとに時刻をずらし、通信失敗時は間隔を広げます。「最新の結果に更新」でも確認できます。Googleの応答時間が加わるため、即時のプッシュ配信ではありません。回答編集中と非表示タブでは取得を休みます。
- 授業を終了するときは「授業」シートの対象授業行を選び、「授業投票」→「授業の受付・閲覧を終了」を使います。理由の非表示・再公開・集計からの除外は「回答」の対象行で行います。終了した授業の票も全体集計に含まれます。

同じブラウザでの修正・再送は票数を増やしません。別の端末・ブラウザでは別の参加者として扱うため、厳密な実人数の集計ではありません。

## Google側のコードを更新するとき

1. `poll/core.cjs`、`poll/Code.gs`、`poll/store.gs`、`poll/cleanup.gs`、`public/02-04-poll/` のソースを編集します。
2. 教材フォルダーで `node scripts/package_communication_poll.mjs` を実行します。
3. 生成した `poll/google/Code.gs` と `poll/google/Index.html` を、既存のApps Scriptの「コード.gs」「Index.html」へコピーして保存します。負荷確認用に `poll/google/LoadTest.html` も「LoadTest.html」として追加します。`store.gs` と `cleanup.gs` は生成したCode.gsに含まれるので、別にGoogleへ追加しません。
4. 「デプロイ」→「デプロイを管理」で既存Webアプリを編集し、「新バージョン」をデプロイします。保存だけでは公開中の画面は更新されません。同じデプロイを更新すればURLは変わりません。
5. 教材と先生用スプレッドシートを再読み込みします。

新しい保存先へコピーするときは、コピー先で「保存先を初期設定（コピー後も実行）」を実行し、別のWebアプリとして公開します。生徒へ保存先シートを公開する必要はありません。

## 教材をビルドする

接続先は `public/02-04-poll/config.json` の `webAppUrl` です。末尾が `/exec` の公開URLを指定します。URLを変えた場合は教材も再ビルドします。

```powershell
$env:PAGES_BASE_PATH = '/YSFH-Infomatics-2026'
npm.cmd run build
```

GitHubのmainブランチへのpushで、既存のGitHub Pages公開処理が教材をビルドします。

## Googleへ送らずに確認する

ビルド後、`node scripts/serve_communication_poll.mjs` を起動し、以下を開きます。

`http://127.0.0.1:3065/YSFH-Infomatics-2026/units/02-04/?poll=local`

新しいローカル保存先の初期コードは `0123` です。先生用リンクは `tmp/02-04-poll/teacher-url.txt` に出力されます。このフォルダーには確認用回答・管理情報が入るため、Gitの管理対象から除外しています。

```powershell
node --experimental-strip-types --test tests/communication-*.test.mjs
node scripts/test_communication_poll_api.mjs
node scripts/test_communication_poll_free_api.mjs
```

APIテストは確認用サーバーを起動して実行します。40人×4課題×2回の同時送信と再送を確認します。これはローカル処理の検証であり、Googleの授業規模での応答速度を保証するものではありません。

## 40人が同時に使うための保存・更新方式

- 投票の受理はシート書き込みの順番待ちをしません。まずScriptPropertiesの永続受信箱へ、送信番号ごとに保存してから成功を返します。消える可能性があるCacheServiceには回答を預けません。
- 結果はシートの既存票と受信箱の新しい票を合成します。シートへの反映待ちでも、本人とクラスの集計に含まれます。
- 結果取得時に、一つの実行だけがロックを取り、保存待ちの回答をまとめて範囲書き込みします。他の実行はロックを待たず、共有キャッシュと受信箱から結果を返します。反映処理は最短6秒間隔です。Googleの応答時間により遅れる場合があります。
- 過去の全回答・送信履歴は20秒の共有キャッシュを使います。日本語の理由が増えて100KBを超えても、一項目の制限を超えないよう分割します。キャッシュを失ってもシートと永続受信箱から復元します。
- 保存済みの送信番号の再試行は増票せず、修正は同じ投票回の票を置き換えます。保存途中の失敗では受信箱を消さず、次の反映で回復します。
- 受信箱の容量に余裕を確保し、満杯の場合は成功を返さず、端末側に下書きと送信番号を残して自動再送します。
- 全員が保存直後に画面を閉じた場合、シート反映が残る場合があります。スプレッドシートを開くと反映を試みます。メニューの「保存待ちの回答をシートへ反映」でも確定できます。回答行を手動削除する場合は、先にこの操作を行ってください。
- 参加の接続も端末ごとに分散し、混雑エラー時は自動で再試行します。問題文と選択肢は接続を待たずに表示します。Google画面自体の読み込み失敗も自動で再接続します。

### 実際のGoogleで40人分を確認する

1. シートを再読み込みし、「授業投票」→「40人同時利用の確認画面を作る」を選び、教材の `config.json` に設定した `/exec` の投票URLを入力します（同じプロジェクトに複数のデプロイがある場合にも、授業で使う公開先を確認するためです）。
2. 表示されたURLを開き、「40人の参加・投票・閲覧を同時に確認する」を押します。4つの独立したGoogle画面から10人ずつ、合計40人分の参加・320票・40回の同一送信の再試行・結果取得を実行します。
3. 各課題が初回40票・考え直し40票となること、処理時間と再試行回数を確認します。単一端末での模擬利用なので、学校の40台の端末・回線の状況まで再現するものではありません。
4. 終わったらシートの「確認用の授業を終了する」を選びます。確認用の授業には `testing` 属性を付け、全クラス集計へ混ぜません。実授業の回答は変更しません。

Google Apps Scriptの同時実行・日次サービス上限は残ります。上限を無くす仕組みではなく、一件の実行を短くし、同時刻の通信とシート操作を減らす設計です。公式の制限：<https://developers.google.com/apps-script/guides/services/quotas>

実データ体験はUCIのBike Sharingを使用しています。出典・ライセンス・列の対応は `public/data/02-04/provenance.json` と教材内に記載しています。通信史・人数のイラストは本教材用の生成画像です。

### テストデータを整理する

「授業投票」→「テストデータを退避して削除」で、`testing: true` の負荷確認用授業と、実装時に記録した確認用授業IDのみを整理します。授業名や4桁コードだけでは判定しません。「授業」シートの見える列だけ空にされ、隠し列の内部データが残った確認用授業も対象です。

先に保存待ちの回答をシートへ反映し、授業・回答・送信記録をそれぞれ「退避_」で始まるシートへ保存します。各行の「元データ（復元用JSON）」列で内容を照合した後に、元の管理シートから対象行を削除し、集計キャッシュを更新します。退避確認に失敗した場合は元の行を削除しません。退避シートは集計しません。実際のクラス回答・コードなし全体投票の回答は残ります。
